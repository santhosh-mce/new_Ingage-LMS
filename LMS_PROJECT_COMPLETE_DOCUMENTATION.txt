1. PROJECT OVERVIEW
================================================================================
- Project Name: InGage LMS (Enterprise Learning Management System)
- Workspace Folder: d:\Ingage project\nextjs-lms
- Project Purpose: A unified, full-stack enterprise learning platform delivering
  self-paced video courses, interactive knowledge checks, timed quiz assessments,
  capstone project submissions, live instructor-led webinars, career pathways,
  credential skill badges, and cryptographically verifiable PDF certificates.
- Dual-Engine Architectural Model:
  1. Student / Consumer Portal:
     - Public landing page, course discovery catalog, and career roadmap exploration.
     - Interactive course checkout with Razorpay payment processing and coupon engine.
     - Student learning classroom (/courses/[id]/learn) with modular video player,
       HTTP 206 partial content streaming, 10-second skip overlay, auto-resume,
       timed quizzes with attempt counting and network issue resiliency, capstone
       project submissions, and live webinar attendance.
     - Personalized Student Dashboard (/my-courses, /dashboard, /my-learning)
       with real-time progress tracking, weekly goals, enrolled tracks, and badges.
     - Verified Certificate Viewer and PDF Downloader (/certificates, /certificates/[id],
       and public verification portal at /certificate/verify/[code]).
  2. Administrative Operations Portal (/admin):
     - Comprehensive administration dashboard with platform analytics, revenue,
       user enrollment statistics, and recent activity audit logs.
     - Curriculum Studio & Course Builder: title-only fast module creation, draft/publish
       lifecycle, multi-tab curriculum builder (Videos, Quizzes, Projects, Live Classes),
       media uploading with automated duration detection, and drag-and-drop sequencing.
     - Assessment Engine: Question banks with multiple-choice options, answer keys,
       explanations, time limits, passing scores, and attempt limit restrictions.
     - Operations & Commerce Management: Orders audit, transaction monitoring,
       discount coupon management, opportunity board, and granular user role control.

3. ARCHITECTURE OVERVIEW
================================================================================
The InGage LMS architecture is a modern, unified monolithic full-stack application
built entirely inside the Next.js App Router framework. It integrates client-side
rendering, server-side data fetching, edge security middleware, RESTful API route
handlers, and direct database persistence through Prisma ORM.

Architecture Layering:
1. Edge Middleware Layer (src/middleware.ts):
   - Intercepts incoming HTTP requests at the edge.
   - Extracts authorization tokens from Authorization header (Bearer) or AUTH_TOKEN cookie.
   - Verifies JWT signatures using Web Crypto API (crypto.subtle).
   - Enforces the strict Role-Based Route Matrix:
     * Unauthenticated users -> Redirected to /login?redirect=<target>
     * Authenticated ADMIN users attempting to access student checkout -> Redirected to /admin
     * Authenticated STUDENT users attempting to access /admin -> Redirected to /my-courses
     * Root URL (/) -> Redirects ADMIN to /admin, STUDENT to /my-courses, or renders Landing Page if guest.
2. Presentation / UI Layer (src/app, src/views, src/components, src/admin):
   - Server Components for SEO, layout structures, and metadata tags.
   - Client Components ('use client') for interactive learning, video player controls,
     quiz taking, drag-and-drop curriculum builder, and real-time state sync.
3. State & API Client Layer (src/store, src/context, src/api):
   - Redux Toolkit manages slices: auth, courses, careers, certificates, projects, opportunities.
   - React Context (AuthContext) manages active user state and authentication lifecycle.
   - Axios instance in src/api/authApi.ts automatically attaches Bearer tokens.
4. Backend API Route Handlers (src/app/api):
   - RESTful API handlers for courses, curriculum, quizzes, projects, live classes,
     enrollments, payments, analytics, certificates, and administration.
   - Uses getSessionUser() and requireAdmin() helper functions in src/lib/auth.ts.
5. Data Access Layer (src/lib/prisma.ts, src/generated/prisma):
   - Prisma Client 7.10.0 initialized with @prisma/adapter-pg over connection pooling.
   - Communicates with PostgreSQL database instance.

5. IMPORTANT FILES AND THEIR RESPONSIBILITIES
================================================================================
1. src/middleware.ts:
   - Primary security boundary for the LMS platform.
   - Verifies incoming JWT tokens using the Web Crypto API (crypto.subtle).
   - Enforces role-based redirects: ADMIN users to /admin, STUDENT users to /my-courses.
   - Secures API endpoints (/api/admin/* requires ADMIN; /api/profile/* requires login).

2. src/lib/prisma.ts:
   - PostgreSQL connection pooler and PrismaClient singleton.
   - Configures @prisma/adapter-pg over pg.Pool.
   - Bypasses SSL certificate rejection in hosted cloud database environments.

3. src/lib/auth.ts:
   - Backend authentication utility functions:
     * hashPassword(password: string): Bcrypt 10 rounds hashing.
     * comparePassword(password: string, hash: string): Password comparison.
     * signToken(payload: TokenPayload): Issues 24-hour JWT token.
     * verifyToken(token: string): Validates and decodes JWT payload.
     * getSessionUser(req?: Request): Resolves authenticated user from DB via token.
     * requireAdmin(req?: Request): Guards admin API endpoints with 401/403 responses.

4. src/lib/fileServer.ts:
   - Video and media streaming engine.
   - Implements HTTP 206 Partial Content Range header parsing.
   - Allows seamless seeking, timeline scrubbing, and high-performance video streaming.
   - Searches local uploads roots (uploads, public/uploads) with directory traversal protection.

5. src/lib/certificateService.ts:
   - Course completion eligibility calculator.
   - Evaluates video watch progress (100% of videos completed), quiz completion (100% passed),
     and capstone project completion.
   - Generates unique certificate numbers in format ING-YYYY-XXXXXX and verification codes.

6. src/views/CourseLearnPage.tsx:
   - Central learning environment for students.
   - Houses the video player, curriculum sidebar, progress tracker, and dynamic tabs.
   - Integrates 10-second skip overlay, centered next-video recommendation, and video resume.

7. src/views/learn/StudentQuizView.tsx:
   - Student Quiz List & Knowledge Checks view.
   - Displays real-time attempt tracking in used / max format (e.g. 0/1, 1/1, 1/2, 2/2).
   - Enforces Start button disablement when usedAttempts >= maxAttempts.
   - Detects and represents attempts interrupted by network failures.
   - Displays a small (?) icon with interactive popover explaining network interruption.

8. src/admin/pages/AdminAddCoursePage.tsx & AdminContentStudioPage.tsx:
   - Comprehensive course authoring studio for administrators.
   - Multi-tab curriculum builder: Videos, Quizzes, Projects, Live Classes.
   - Supports automated video duration detection, drag-and-drop reordering, and publishing.

9. src/app/api/payments/create-order/route.ts & verify/route.ts:
   - Commercial checkout and payment engine.
   - Creates Razorpay order IDs and validates discount coupon codes against limits.
   - Cryptographically verifies Razorpay payment signatures (HMAC-SHA256).
   - Automatically provisions course and career track enrollments upon successful verification.

10. src/context/AuthContext.tsx & src/store/slices/authSlice.ts:
    - Global client-side authentication state.
    - Synchronizes current user data, token persistence in localStorage and cookies,
      and triggers real-time UI updates on login/logout.

6.1. FRONTEND TECHNOLOGY STACK

The InGage LMS frontend is engineered as a unified, full-stack client-server
application built on top of Next.js 16 and React 19. All technologies documented
below have been verified directly against package.json and active source code:

   - Next.js: Version 16.3.6 (App Router paradigm with React Server Components
     and Client Components marked with 'use client').
   - React: Version 19.2.8 & React DOM: 19.2.8 (supports concurrent features,
     useActionState, server components, and modern hydration models).
   - TypeScript: Version 5.x (Strict type checking enabled in tsconfig.json
     with path alias '@/*' resolving directly to './src/*').

2. CSS Framework & Styling Engine:
   - Tailwind CSS: Version 4.x configured via @tailwindcss/postcss (^4) in
     postcss.config.mjs and imported in src/app/globals.css.
   - Styling Approach: Utility-first CSS classes, CSS variables, and responsive
     prefixes (sm:, md:, lg:, xl:, 2xl:) without third-party component frameworks.
   - Design System Palette:
     * Primary Emerald Brand: #00A86B, #008F5B, emerald-500, emerald-600.
     * Accent Orange: #F97316, #EA580C (Buttons, quiz progress indicators).
     * Accent Amber / Yellow: #FEF7D6, amber-500 (Quiz network notices, warning badges).
     * Neutral Slate: slate-900 (deep dark surfaces), slate-50/100 (light dashboard backgrounds).
     * Border / Dividers: border-slate-200/80, border-slate-100.

3. UI Component Libraries & Iconography:
   - Lucide React: Version 0.546.0 (High-performance tree-shakeable SVG icons
     used universally across headers, sidebars, buttons, video player, and cards).
   - Motion (Framer Motion): Version 13.4.4 (Powers micro-animations, slide-ins,
     accordion transitions, and modal backdrop fades).

4. State Management & Context Architecture:
   - Redux Toolkit: Version 2.12.0 (@reduxjs/toolkit) with react-redux (9.3.0).
     Store configured in src/store/index.ts with domain slices:
     * authSlice: User credentials, authentication status, tokens.
     * courseSlice: Enrolled courses, active lessons, playback timestamps, progress.
     * careerSlice: Career pathways, enrollments, milestones.
     * certificateSlice: Earned certificates, verification statuses.
     * opportunitySlice: Job postings, filters, applications.
     * projectSlice: Capstone project briefs and student submissions.
   - React Context API:
     * AuthContext (src/context/AuthContext.tsx): Manages currentUser, isAuthenticated,
       login(), logout(), and AuthModal open/close states.

5. API Communication & Data Fetching:
   - Axios: Version 1.20.0 configured in src/api/authApi.ts with default interceptors
     automatically attaching 'Authorization: Bearer <token>' to every outgoing request.
   - Data Fetching Pattern: Client-side asynchronous fetching via useEffect and Redux
     async thunks, with server components used for preliminary metadata and SEO.

6. Media & Video Playback:
   - Native HTML5 Video Element with custom overlay UI controls in CourseLearnPage.tsx.
   - HTTP 206 Partial Content Range streaming support via Next.js route handlers.
   - Features: Time tracking, timeline scrub, 10-second skip overlay, centered next-video card.

7. Client-Side PDF Generation & Canvas Rendering:
   - jsPDF (4.2.1) & html2canvas (1.4.1): Renders high-resolution vector and canvas
     certificates on the client for direct PDF download in src/utils/certificatePdfGenerator.ts.

8. Commercial & Payment Integration:
   - Razorpay Web Checkout JS SDK dynamically injected into the client window during
     checkout, communicating with backend order creation and verification APIs.

9. Notifications & Toast System:
   - Custom interactive toast system embedded in AppShell.tsx and CourseLearnPage.tsx
     providing slide-in alerts with auto-dismiss timers for network and progress updates.

6.9. FRONTEND API COMMUNICATION
--------------------------------------------------------------------------------
1. Axios Instance Configuration (src/api/authApi.ts):

     * Catches HTTP 401 Unauthorized errors and dispatches session expiration handlers.

2. End-to-End Execution Chain Example:
   User clicks "Submit Quiz" in StudentQuizView.tsx
   ──► handleAttemptSubmit() event handler triggers in React component
   ──► quizApi.submitQuizAnswer(courseId, lessonId, payload) invoked
   ──► Axios POST to /api/courses/[id]/quiz/submit?lessonId=[lessonId]
   ──► Backend Route Handler verifies JWT, grades answers, updates lesson_progress
   ──► JSON Response returned with { score, passed, attemptCount, hasNetworkIssue }
   ──► React local state updates result view; Redux dispatches progress refresh
   ──► UI displays score modal, updates attempt count to 1/1, and disables Start button.


6.10. AUTHENTICATION AND ROUTE PROTECTION
--------------------------------------------------------------------------------
1. Edge Middleware Boundary (src/middleware.ts):
   - Evaluates incoming HTTP requests before React rendering starts.
   - Verifies JWT signatures with Web Crypto API (crypto.subtle).
   - Redirects unauthenticated requests to /login?redirect=<target>.
   - Redirects authenticated ADMIN users attempting student routes to /admin.
   - Redirects authenticated STUDENT users attempting admin routes to /my-courses.

2. Client-Side Defense-in-Depth Guards:
   - AdminLayout (src/admin/AdminLayout.tsx):
     * Checks mounted, currentUser, and isAdminRole.
     * If user is not admin, replaces window.location with '/my-courses'.
   - StudentLayout (src/components/layout/StudentLayout.tsx):
     * Checks mounted, currentUser, and role.
     * If admin user accesses /my-courses, replaces window.location with '/admin'.
   - ProtectedRoute (src/components/ProtectedRoute.tsx):
     * Reusable wrapper component enforcing role authorization and loading spinners.


6.11. FRONTEND DATA FLOW TRACES
--------------------------------------------------------------------------------
Workflow A: Admin Creates Course & Adds Modules
- Admin inputs course title in AdminAddCoursePage.tsx.
- Clicks "Create Course" ──► adminApi.createCourse() ──► POST /api/admin/courses.
- Response returns new course ID. Admin switches to Curriculum tab.
- Clicks "Add Module" ──► adminApi.createSection() ──► POST /api/admin/courses/[id]/sections.
- Module renders in UI; Admin uploads video ──► POST /api/admin/media/upload.
- Lesson metadata saved ──► POST /api/admin/sections/[id]/lessons.

Workflow B: Student Watches Video Lesson
- Student selects video in CourseLearnPage.tsx.
- HTML5 <video> requests /api/uploads/video with HTTP Range headers.
- Player streams chunked video; onTimeUpdate dispatches periodic saveProgress().
- At 90% watch duration, POST /api/progress/save-progress marks completed = true.
- Redux completedLessonIds array updates; sidebar item displays green checkmark.

Workflow C: Student Quizzes with Attempt Limits & Network Interruption
- Student opens Quizzes tab in CourseLearnPage.tsx.
- StudentQuizView renders quiz row with attempt count (e.g. 0/1).
- Student clicks Start; QuizAssessmentView loads questions from /api/courses/[id]/quiz.
- Student completes answers and submits.
- If network connection fails: catch block catches network error, flags hasNetworkIssue: true,
  marks attempt as used locally, queues background sync, and returns to quiz list.
- Quiz list shows 1/1, Start button disabled (grey), small (?) icon visible with tooltip.

7. BACKEND ARCHITECTURE
================================================================================
The backend consists of 129 RESTful Next.js Route Handlers (src/app/api):
- Request Lifecycle:
  1. Request reaches Next.js Edge Middleware (src/middleware.ts).
  2. Middleware validates path patterns, extracts JWT token, and checks permissions.
  3. Valid requests proceed to the corresponding Route Handler in src/app/api.
  4. The handler calls getSessionUser(req) or requireAdmin(req) from src/lib/auth.ts.
  5. Business logic interacts with PostgreSQL through the Prisma ORM singleton (src/lib/prisma.ts).
  6. BigInt identifiers and decimal values are serialized using serializeData(data).
  7. A JSON response with standard HTTP status codes (200, 201, 400, 401, 403, 404, 500) is returned.
- Service Layer Pattern:
  * Authentication: src/lib/auth.ts (Bcrypt, JWT, DB session verification)

9. USER ROLES AND PERMISSIONS
================================================================================
The LMS enforces three primary user roles defined in the users table:
1. ADMIN (including ROLE_ADMIN, SUPER_ADMIN, ADMINISTRATOR):
   - Permissions: Full administrative control over all platform modules.
   - Course Access: Unlimited bypass access to all courses and learning materials
     without payment or enrollment requirements.
   - Prohibited Actions: Administrators cannot purchase courses or initiate student checkouts.
   - Accessible Pages: All /admin/* routes, public catalog, and course preview classroom.
2. STUDENT (Default role for registered users):
   - Permissions: Can browse courses, purchase enrollments, watch lessons, take quizzes,
     submit capstone projects, attend webinars, and download earned certificates.
   - Restrictions: Strictly blocked from /admin/* pages (redirected to /my-courses).
   - Course Access: Restricted strictly to paid or free enrolled courses.
3. INSTRUCTOR / STAFF (Sub-role):
   - Permissions: Uploading curriculum media, managing course lessons, grading projects.
   - Inherits administrative authoring capabilities when assigned by administrators.

10. AUTHENTICATION AND AUTHORIZATION
================================================================================
- Password Authentication Flow:
  1. Student/Admin registers via /api/auth/register or signs in via /api/auth/login.
  2. Passwords are encrypted using bcryptjs (10 salt rounds).
  3. Upon successful validation, a JWT token is generated containing userId, email, role, name.
  4. The JWT token is returned in the response body and set in the HTTP-only AUTH_TOKEN cookie.
  5. The client stores the token in localStorage and includes it in Axios Bearer headers.
- OAuth 2.0 Integration:
  - Supports Google OAuth login (/api/auth/callback/google, /api/auth/google).
  - Matches or creates user record in the users table with provider = 'google'.
- Edge Authorization Verification:
  - src/middleware.ts intercepts incoming requests.
  - Verifies token signature with Web Crypto HMAC-SHA256.
  - Enforces route boundaries based on token role claims.

18. ENROLLMENT AND PAYMENT WORKFLOW
================================================================================
- Commercial Checkout Architecture:
  1. Price Discovery: Client requests course or career track pricing.
  2. Coupon Validation: POST /api/discounts/validate verifies coupon active status,
     date window, minimum purchase amount, and per-user usage caps.
  3. Order Creation: POST /api/payments/create-order:
     - Validates user is not ADMIN.
     - Checks existing active enrollment to prevent duplicate charges.
     - Calculates final amount after discounts.
     - Generates Razorpay Order via Razorpay Node SDK.
     - Inserts record into orders table with status 'PENDING'.
  4. Client Payment: Razorpay Checkout Web modal opens with order_id and key_id.
  5. Payment Verification: POST /api/payments/verify:
     - Verifies HMAC-SHA256 signature: crypto.createHmac('sha256', secret).update(order_id + '|' + payment_id).digest('hex').
     - Updates order status to 'PAID'.
     - Creates transaction record in payments table with status 'PAID'.
     - Upserts record in enrollments table with status 'ACTIVE' and progress_percentage = 0.

19. LEARNING PROGRESS TRACKING
================================================================================
- Lesson Progress Tracking (lesson_progress table):
  * Primary tracking entity linking enrollment_id and lesson_id.
  * Fields: completed (Boolean), last_position_seconds, total_duration_seconds,
    watch_duration_seconds, watched_percentage, completed_at, last_accessed_at.
  * Atomic upsert via raw SQL in /api/progress/save-progress ensures multi-tab safety.
- Overall Course Progress:
  * Course progress percentage = (completedLessonsCount / totalLessonsCount) * 100.
  * Stored in enrollments.progress_percentage.
  * When progress reaches 100%, enrollment.status is set to 'COMPLETED' with completed_at timestamp.

20. REPORTS AND CERTIFICATION
================================================================================
- Certification Eligibility Engine (src/lib/certificateService.ts):
  * Evaluates three mandatory criteria:
    1. Video Lessons: 100% of video lessons completed (watched >= 90%).
    2. Quiz Assessments: 100% of quizzes completed with passing score.
    3. Capstone Projects: 100% of required projects submitted.
  * When all criteria are satisfied, isEligible evaluates to true.
- Certificate Generation:
  * Claimed via POST /api/certificates/claim/[courseId].
  * Generates unique certificate number: ING-YYYY-XXXXXX (e.g. ING-2026-000123).
  * Generates cryptographic verification code: ING-YYYY-VXXXX (e.g. ING-2026-V8A2F).
  * Inserts record into certificates table.
  * Verifiable on public portal at /certificate/verify/[code].
  * Rendered as high-resolution PDF certificate using html2canvas and jsPDF.

24. FRONTEND-TO-BACKEND DATA FLOW
================================================================================
Example 1: Student Watches Video Lesson
1. User clicks lesson in CourseLearnPage.tsx sidebar.
2. React state activeLesson updates; HTML5 <video> src loads /api/uploads/videos/video.mp4.
3. Browser requests video with HTTP Range header (bytes=0-...).
4. Route handler /api/uploads/[...path] calls serveFileWithRange in src/lib/fileServer.ts.
5. Node.js fs.createReadStream streams binary chunk with HTTP 206 Partial Content.
6. Player triggers onTimeUpdate event. Every 5 seconds, client calls saveProgress().
7. Axios posts payload to /api/progress/save-progress.
8. Handler runs SQL upsert on lesson_progress. If watched >= 90%, marks completed = true.
9. Response returns updated completion percentage; client UI updates green checkmark.

Example 2: Student Takes Quiz with Network Resiliency
1. User opens Course Quizzes tab. StudentQuizView.tsx renders quiz list.
2. Component fetches /api/courses/[id]/content. Attempts rendered as used / max (e.g. 0/1).
3. Student clicks Start. QuizAssessmentView loads questions from /api/courses/[id]/quiz.
4. Student answers questions and clicks Submit.
5. If connection active: POST /api/courses/[id]/quiz/submit grades answers, writes score,
   and increments attempt count in lesson_progress.
6. If network disconnection occurs during quiz submission:
   - Frontend catches network error, marks attempt as used locally, sets hasNetworkIssue = true.
   - Enqueues background sync once window.navigator.onLine fires.
   - Returns to quiz list: Start button becomes disabled (1/1); small (?) icon appears.
   - Tooltip displays network interruption explanation.
   - State persists on backend and across page refreshes.

32. SECURITY AND ACCESS-CONTROL OBSERVATIONS
================================================================================
1. Edge Middleware Protection:
   - src/middleware.ts guarantees that unauthenticated requests to protected student
     or administrative routes are intercepted before hitting application code.
2. Password Security:
   - Passwords hashed using bcryptjs with 10 salt rounds. Plaintext passwords never stored.
3. Cryptographic Signature Verification:
   - Razorpay payment verifications validate HMAC-SHA256 signatures server-side.
4. Directory Traversal Defense:
   - src/lib/fileServer.ts strips relative path modifiers (..) to prevent unauthorized
     access to system files.
5. Role Separation Enforcement:
   - Administrators cannot buy courses, and students cannot access administrative panels.
